# Canonical manifest of state that backup tooling round-trips.
# Single source of truth for:
#   - scripts/backup-workspace.sh        (host-driven manual snapshot)
#   - scripts/chad-backup-to-github.sh   (in-sandbox cron push to chad-state)
#   - scripts/chad-restore-from-github.sh (cold-boot disaster recovery)
#
# Format: a sectioned list. Each line is one of:
#   - "[section]"               — switches the active section
#   - "filename" or "dir/"      — relative entry within the active section
#   - "# comment" or blank line — ignored
#
# Sections:
#   [workspace]    Files relative to /sandbox/.openclaw/workspace/ — persona, memory roots.
#   [runtime]      Files relative to /sandbox/.openclaw-data/      — orchestration state.
#   [runtime-dirs] Directories relative to /sandbox/.openclaw-data/ — recursive backup.
#   [exclude]      Documentation only. NEVER backed up. Lists what we deliberately leave
#                  out, with rationale, so future contributors don't accidentally add
#                  sensitive or ephemeral data to the runtime sections.
#
# When backup scripts encounter a section they don't understand, they SKIP it (forward-
# compatible). When restore encounters a section it doesn't understand, same — skip.
#
# The memory directory under workspace is handled separately by both backup scripts
# (recursive, glob-based) and is not listed here.
#
# Adding state: append under [runtime] or [runtime-dirs], then re-run scripts/chad-setup.sh
# (or `install_to_share_chad scripts/chad-workspace-files.txt`). Both backup scripts pick
# it up on the next invocation; no script edit needed.
